## Split rule (stable, reproducible)

```
bucket(lesson_id) = int(md5(lesson_id.encode("utf-8")).hexdigest(), 16) % 3
```

This report owns **bucket 2**: **41 lessons, 81 offending pairs**. (Buckets: 0 → 43 lessons, 1 → 39, 2 → 41.)
The rule is pure `md5` over the exact lesson id string, so it is re-derivable without this file.

## What "compliant candidate" means here

A replacement is **compliant** only if it clears both gates the validator applies:

1. `LEVEL_ORDER.index(sentence.level) <= LEVEL_ORDER.index(lesson.level)` where
   `LEVEL_ORDER = (pre-n5, n5, n4, n3, n2, n1)`, and
2. `load = |new_kanji| + |new_vocab| <= BUDGET[lesson.level]` (`pre-n5:0, n5:1, n4:2, n3:2`), computed against
   that lesson's own `cumulative_known_set` exactly as the validator computes it (kanji = characters present in
   `corpus/kanji/*.json`; vocab = `split_mode == "C"` tokens carrying a vocab slug).

On top of that I required the candidate to carry the **same teaching point** (shared `grammar` entry or the same
target vocab/pattern) and to **match register**. Real sentences (`provenance.ai_generated == false`) were preferred
over generated ones per spec §1.2. Search covered all 5 889 records in `corpus/sentences/bank.json`.
